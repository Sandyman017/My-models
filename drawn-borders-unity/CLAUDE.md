# Drawn Borders in Unity — Maz's strategy game, moving to Unity

The web game lives in `../drawn-borders` (read its `CLAUDE.md`: who Maz is, how we work). This folder is the start of a Unity version, made because the web map lags and Unity can look much better. Maz plays on Windows (GTX 1650) and opens this folder in Unity Hub with **Unity 6**; cloud sessions cannot run Unity, so every change is checked with the tools in `Tools/` (see `Tools/README.md`) and Maz tests it on his PC.

## Done so far (part 1: the founding step)
- `Assets/DrawnBorders/Engine` (pure C#, no Unity): `Noise` (mulberry32, hash2, value noise, fbm — bit-for-bit the web engine), `World` (terrain, levels, deposits, coast), `Rivers` (`RiverField` priority flood, `RiverGeo` navigable systems, `SeaGeo` ocean and shore, `PortSeaCell`, `BeachSeaCell`), `Borders` (`ClaimFromPath`, `MeasureShape`, `Traits`), `Founding` (`FoundingPreview`: people, farmland, towns via `PlaceTowns` with `Rng(7)`, the factors list worded as the web panel; `SampleShape`). The full economy is not ported, so the preview has no Output figure. Sorts that must match JS use a stable order (by cell on ties); `Math.round` is `Noise.JsRound`.
- `Assets/DrawnBorders/Bake/MapBaker.cs` (pure C#): bakes at 24 px a cell (2304×1536, about 2 s on 4 cores): colour (the web map's palette; alpha = baked sun shadow from the north-west), data (r = coast: 0.5 + (e − sea) × 1.25, g = distance to the nearest river ÷ 0.3, b = its half width ÷ 0.1, a = open sky), normals, heights (land: (height − sea) × 3.2, sea floor × 1.6). Mountains use ridged gradient noise (`Ridges`), not the web map's ridges, which looked like bubbles in 3D. Rivers are the web map's traced lines (`RiverLines`), stored as distances so the shader draws them sharp at any zoom.
- `Assets/DrawnBorders/Game`: `Boot` (starts the game in any scene on Play), `FoundingGame` (+ `FoundingUi`: the panel and labels in IMGUI; + `ProvincesStep`, below), `MapView` (textures, the land mesh at 8 points a cell, the sea sheet, every nation's land from `PoliticalMap`, deposits, hover, 3D towns, ray to the ground), `CameraRig`, `InputState` (classic Input, or IMGUI events when the project allows only the new Input System).
- Shaders in `Assets/DrawnBorders/Resources/DrawnBorders` (CG, no LightMode tag, own lighting in `DrawnBorders.cginc`: they work in the built-in pipeline and URP, Gamma or Linear).
- No `Packages/` or `ProjectSettings/` are committed: Unity makes them for whatever version Maz opens it with.
- First run in Unity 6.6 (6000.6.7f1) on Maz's PC: textures with mip levels are filled with `SetPixelData` (the full-size level) and `Apply` makes the rest, because `LoadRawTextureData` wants every level and throws. From far away the sea's sharp sun glints fade (they were a field of white specks).

## Moving the whole game: one rules engine, the web game's JavaScript, running inside Unity
Maz approved a 9-part plan (Oct 2026): the rules stay in ONE place, `../drawn-borders/src/engine`, and Unity runs that JavaScript, so rules, rival AI and saves stay identical and the web/Windows version keeps working. Unity draws everything (3D map; panels rebuilt in UI Toolkit). Part 1 (done): the engine runs in Unity with exactly the same results as in Node, as fast. Part 2 (done): founding step 2, the provinces, on the engine. Part 3 (done): time runs, seasons on the map, news, decisions. Next: part 4, the panels (first the letters: envoys and demands, which the opening war needs; then the realm, economy, laws, projects); then armies, trade, the cabinet, statistics, saves, and a Windows installer. Maz does not want explanations of the technique: build part after part, and tell him in a few simple words what he can now do in the game.
- **PuerTS 3.0.3 with V8** (Tencent; the official GitHub release `Unity_v3.0.3`, files `PuerTS_Core_3.0.3.tar.gz` and `PuerTS_V8_3.0.3.tar.gz`) in `Assets/ThirdParty/PuerTS/core` and `/v8`, with only the Windows x64 binaries (`Plugins/x86_64`: `PuertsCore.dll`, `WSPPAddon.dll`, `PapiV8.dll` 19 MB); other platforms were taken out. Its own `.meta` files are committed (they hold the plugins' platform settings); no change to `Packages/manifest.json`. To update it: replace both folders from a newer release and remove the other platforms again.
- `Assets/DrawnBorders/Js/JsEngine.cs`: loads `Resources/DrawnBorders/engine-bundle.txt` into a V8 world (`new ScriptEnv(new BackendV8())`, about 1.5 s); `Run(code)` and `Eval<T>(expression)`. The bundle is one classic script, so every engine function and constant is a global afterwards. One JsEngine per thread.
- The bundle is written by `node Tools/js-engine/bundle.js` (`polyfill.js` + `engineSource()` from `../drawn-borders/build.js`): **run it after every engine change** and commit the bundle (`--check` says if it is stale). Unity's V8 has no `Intl`, so `polyfill.js` writes `toLocaleString("en-US")` numbers itself, exactly as the browser does (it rounds the shortest decimal: 1.0005 → "1.001"); it also gives `structuredClone` and a quiet `console` when missing.
- The check (`Tools/README.md`, "The game's JavaScript engine runs the same in Unity"): `Tools/js-engine/check.js` plays seeds 1000, 8919 and 16838 for 12 seasons in Node (`node-check.js`) and in Unity batch mode (`Assets/DrawnBorders/Editor/JsEngineCheck.cs`, `-executeMethod DrawnBorders.JsEngineCheck.Run`, or the menu Drawn Borders → Check the JS engine); `node-check.js --compare` must say `ALL THE SAME`. First result: all the same; a season takes 330–600 ms in both. `Math.random` (only the ministers' salt) is seeded in the check; the real game leaves it random, as the browser does.
- The C# port in `Assets/DrawnBorders/Engine` (world, rivers, borders, founding preview) stays for the founding screen and the map baker; new rules are not ported to C# any more.
- **The game runs the engine on its own thread**: `Assets/DrawnBorders/Js/EngineThread.cs` (made in `FoundingGame.Start`, so the engine starts while the world is baked; the texts are read on the main thread with `JsEngine.Sources`, a loader that also serves PuerTS's own start-up modules, because Unity's `Resources` work only there). `Call(code)` gives a `Task<string>` (for slow calls: founding, seasons), `CallNow` waits (quick calls). `Str`/`Num` write C# values as JavaScript.
- **What Unity asks of the engine** is `Tools/js-engine/bridge.js` (`globalThis.U`, in the bundle after the engine): it holds the one `world` and `game` and calls the engine as the web interface does (`foundNation`, `provChange`, `startWithProvinces`…), answering in JSON for `JsonUtility` (no nulls: -1). Shapes in `Assets/DrawnBorders/Game/GameData.cs`. Add new calls there, never rules.
- **Founding, step 2** (`Game/ProvincesStep.cs`, a part of `FoundingGame`; phases `Draw → Founding → Provinces → Started`): "Found this nation" runs `U.newGame(seed, cells, name)` (setupGame: the rivals and everyone's provinces). The panel (IMGUI) lists your provinces (name boxes: saved on Enter, a click elsewhere or Start; "change" makes the next town the capital), "Divide it for me" and 1–5, the pen (left-drag on the map: `U.penCells`, then a card: new province / add it to … / cancel), "Draw my borders again", "Start with these provinces" (`U.start`: the first lines of the story). Panel buttons only set `queued`, done in `Update`, so a panel never changes in the middle of an IMGUI frame. Names on the map: nations when far out, your provinces, towns (★ capitals).
- **Time and seasons** (`Game/Seasons.cs`, phase `Play`; as the web game's ui/51-17e-…): a season lasts 36 / 18 / 8 s (speeds 1–3), Space pauses, the game starts paused. `U.endSeason()` runs on the engine thread (the rivals act on the plans `deliberate()` made at the season's start, as the web game's `startDeliberation`), and gives the news (five at most, repeats within six seasons only in the report: `seasonHeadlines`/`pushNews`), the full season report, why time stops by itself (`autoPauseReason`) and a fallen government. Then the map, the top bar (`U.hud()`: the web game's `hudHtml` figures and notes) and the decisions (`U.decisions()`, `U.decide(id, option)`: a new one opens by itself; not deciding lets the ministers choose when it expires) are loaded again. Time stops while a decision card, the season report or the end card is open. Not in Unity yet: letters (envoys, demands; they go unanswered, which counts as a refusal), the web's people news (`seasonPeopleNews`) and Assembly drafts (both in ui/ files, not in the engine), Claude for the rivals, saving.
- **Every nation on the map**: `Game/PoliticalMap.cs` (8 pixels a cell: each nation's (and the wild land's) cells bilinear + blurred, every pixel to the strongest; then each pixel's distance to its land's border, by Felzenszwalb's distance transform; provinces the same, inside each nation). `Terrain.shader` reads the four pixels around a point itself (`PolLayer`) and blends their distances signed by side, so borders are sharp at any zoom and each side gets its own colour (two-tone border lines, a light wash, the player's provinces tinted while dividing, thin light province lines away from national borders). Within 2.5 pixels of a border the distance is measured between pixels (the two strongest masks' difference over its slope), else borders at a slant show steps of 1/8 cell up close. The first try, a blended "strongest minus second" field, drew stripes wherever the second-strongest land changed: don't go back to it. It is rebuilt on the main thread after every change and season (well under a second).
- **Seeing the game without Unity on screen** (Maz may say no to Claude driving his editor): `Assets/DrawnBorders/Editor/PlayCheck.cs` plays the founding through in batch mode and saves map pictures (`Tools/README.md`). The panels and names are IMGUI and do not show in batch mode.
